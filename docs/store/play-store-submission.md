## 2. 데이터 안전(Data safety) 설문 답안

> Play Console > 앱 콘텐츠 > 데이터 보안. **틀리면 나중에 앱이 내려간다** — 아래는 코드에서 확인한 실제 동작이다.

### 공통 답변
| 질문 | 답 | 근거 |
|---|---|---|
| 데이터를 수집·공유하는가 | **예** | 아래 표 |
| 전송 중 암호화되는가 | **예** | 전 구간 HTTPS |
| 사용자가 데이터 삭제를 요청할 수 있는가 | **예** | 방침 §7 + 설정 > 의견 보내기 · jinho@zinosb.com |
| 데이터가 제3자와 **공유**되는가 | **아니요** | Supabase/Vercel/Anthropic 은 모두 *서비스 제공업체(처리자)* 로, 구글 정의상 '공유'에 해당하지 않는다. 우리 지시 범위에서만 처리한다 |
| 독립 보안 검토를 받았는가 | 아니요 | — |

### 수집하는 데이터 유형

| Play 분류 | 세부 항목 | 수집 | 필수/선택 | 목적 | 실제 위치 |
|---|---|---|---|---|---|
| 개인 정보 → 이름 | 이름 | ✅ | 필수 | 앱 기능, 계정 관리 | `driver_profiles` |
| 개인 정보 → 사용자 ID | 사번, 계정 ID | ✅ | 필수 | 앱 기능, 계정 관리 | `driver_profiles` |
| 앱 활동 → 앱 상호작용 | 교육 자료 열람, 게임 실행 기록 | ✅ | 선택 | 분석, 앱 기능 | `audit_log`, `game_scores` |
| 앱 활동 → 기타 사용자 생성 콘텐츠 | 위험요인 제보, 안전 제안, 의견 | ✅ | 선택 | 앱 기능 | `hazard_reports`, `feedback` |
| 사진 및 동영상 → 사진 | 제보 첨부 사진 | ✅ | 선택 | 앱 기능 | `api/safety/hazards` 업로드 |
| 앱 정보 및 성능 → 기타 | 접속 일시·동작 로그 | ✅ | 필수 | 부정 이용 방지, 앱 기능 | `audit_log` |
| 기기 또는 기타 ID | 익명 UUID, 웹푸시 구독 식별자 | ✅ | 선택 | 앱 기능 | `lib/anonymousId`, `push_subscriptions` |

### 수집하지 **않는** 것 (설문에서 반드시 '아니요')
- 위치 정보 (앱은 위치 권한을 요청하지 않는다)
- 연락처·주소록, 캘린더, SMS/통화 기록
- 금융·결제 정보
- 건강·피트니스
- 주민등록번호 등 정부 발급 식별자

> **IP 주소**: 구글 데이터 안전 설문은 IP 를 별도 항목으로 두지 않는다.
> 위 `앱 정보 및 성능 → 기타` 에 포함해 신고하고, 개인정보처리방침에는 명시적으로 적어 두었다.

## 4. 심사 리스크와 대응

### ① 로그인 벽 — 가장 흔한 리젝 사유
심사자가 로그인하지 못하면 "기능을 확인할 수 없음"으로 거절된다.
**대응**: Play Console > 앱 콘텐츠 > 앱 액세스 권한 에 데모 계정을 등록한다.

```
로그인 방법: 첫 화면에서 사번 8자리 입력 → 다음 → 이름 입력
사번: [ 진호가 심사용 계정 발급 ]
이름: [ 동일 ]
비고: 근무표는 로그인 후 홈 화면에서 바로 확인됩니다.
```

> 심사용 계정은 **실제 기관사 개인정보가 아닌** 별도 테스트 계정으로 만들 것.

### ② "사내 전용 앱" 으로 보이는 것
구글은 공개 배포를 허용하지만, 설명이 "특정 사업소 직원 전용"으로 읽히면
용도 제한 앱으로 분류돼 문제가 될 수 있다. 애플은 더 엄격해서 사내 앱을
Business Manager 로 돌려보낸다.

**대응**: §1 설명처럼 **"5호선 승무 업무 정보 앱"** 으로 서술한다.
실제로 실시간 열차 정보·안전 자료·교육 자료가 모두 들어 있으므로 사실 그대로다.
"직원 전용", "OO사업소 내부용" 같은 표현은 쓰지 않는다.

### ③ 상표
앱 이름·아이콘·스크린샷에 **서울교통공사 명칭이나 로고를 쓰지 않는다.**
설명 본문에서 노선(5호선)을 사실로 언급하는 것은 문제되지 않는다.

### ④ 정확한 알람 권한
앱은 `SCHEDULE_EXACT_ALARM` 을 쓴다(근무 알람이 제 시각에 울려야 하므로).
Play 가 용도를 물으면: **"교대 근무자의 출발 시각 알람이 핵심 기능이며, 몇 분만 밀려도
기능이 무의미해진다"** 고 답한다.

## 5. 빌드 명령

```bash
npm run native:keystore   # 최초 1회 — 서명 키 생성 (비밀번호 직접 입력, 백업 필수)
npm run native:aab        # 스토어 업로드용 AAB (versionCode 자동 +1)
npm run native:install    # 폰에 디버그 APK 설치 (QA용)
```

AAB 위치: `android/app/build/outputs/bundle/release/app-release.aab`

## 6. iOS (나중)

Mac + Xcode 가 필요하다. 안드로이드가 통과한 뒤 착수한다.
애플은 사내 앱 판정이 더 엄격하므로 §4-② 포지셔닝이 특히 중요하고,
데모 계정과 **로그인 없이 볼 수 있는 화면**을 준비해 두는 편이 안전하다.
